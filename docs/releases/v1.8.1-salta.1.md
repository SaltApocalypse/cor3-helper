## Highlights

### Smart Sort

The warehouse sorter now groups items for a cleaner, more scalable layout:

- **Rarity sections** stay in the configured order:
  `QUEST > LEGENDARY > EPIC > SUPERRARE > RARE > COMMON`
- Inside each rarity, items are grouped by **height**, with **tall items first**.
- Identical item types stay together.
- Multiple item types can share the same shelf; a type no longer reserves an entire row.
- Items stay **upright** unless their base width exceeds the warehouse grid.
- Rows inside a rarity are uniform in height, avoiding the mixed-size “jagged” look of the old first-fit layout.

On the captured test warehouse (140 items, 214 cells, 12×60), Smart Sort uses 29 rows; the old per-type Horizontal layout used 48 rows.

### Compact Sort

The previous first-fit layout is kept as **Compact Sort** for nearly full warehouses.

### Automatic Fallback

If Smart Sort needs more rows than the warehouse provides:

- The sorter automatically switches to Compact Sort.
- A notice explains why, e.g.:
  `Smart layout needs at least 34 rows (max 30) — used Compact layout instead.`
- If both layouts cannot fit, sorting is rejected without sending any moves.

### Sorting Behavior (unchanged)

- Layouts are fully precomputed before any move.
- Already-correct items are skipped.
- The in-game sorting table is used only for items blocking a target position.
- Moves are serialized; progress is shown.
- Mailbox auto-claim is paused while sorting.
- On failure, items still parked in the sorting table are returned to their original cells where possible.

## Installation

1. Download `cor3-helper-v1.8.1-salta.1.zip` from this release.
2. Extract the archive to a folder.
3. Open `chrome://extensions/` and enable **Developer mode**.
4. Click **Load unpacked** and select the extracted folder (the one containing `manifest.json`).
5. Open [cor3.gg](https://cor3.gg) and log in.
6. Open the extension popup, then use `Smart Sort` in the Inventory section.

## Notes

- Sorting can take a long time because every move is a server round-trip. Do not refresh or close the page while sorting.
- The sorting table must be empty before starting a sort; close/reopen the warehouse window to return any items left there.
- Auto-claim and auto-sell are paused while sorting.
- `versions.json` is updated manually before releases via `npm run sync-versions` / `npm run release:prepare`. The release workflow only warns if it is stale.
